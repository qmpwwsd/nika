# nika 0.3 Session Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From the app's session window, see and switch Claude's permission mode, run any slash command, use `!`,
answer permission prompts, stop a turn, end a session, and pick models from a list. Every mode looks different.

**Architecture:** Everything still goes through the 0.2 pane path: nika reads Claude's TUI through the pane mirror
(`src/mirror.js`) and types through `src/keys.js`. New pure parsers turn mirror rows into a mode and a permission
prompt (`src/mode.js`). A small controller sequences key presses for mode switch and End session
(`src/session-control.js`). New app-tier routes live in `src/api-app.js`, and new UI modules live in `public/`. The
browser tier is unchanged.

**Tech Stack:** Node ≥ 22, ES modules, stdlib only; `node:test`; tmux; vanilla JS/CSS in `public/` under a strict CSP.

**Spec:** `docs/superpowers/specs/2026-11-08-control-panel-design.md` (§2, §4, §5 rows for 0.3, §6, §9 T22 T23
T26, §10 V11–V16). Read it with this plan.

## Global Constraints

- Zero npm runtime and dev dependencies; no new Rust crate.
- Subprocesses only through `execFile` with fixed argv; tmux text through `send-keys -l --`; named keys only from
  `KEY_NAME` (`src/ids.js`).
- Every new route is under `/api/app/*` (app tier only). Never mounted on :3335. Browser tier unchanged.
- Pane actions reuse `eligiblePane()` in `src/api-app.js`: live Claude pane or nika-started pane whose current
  command matches `CLAUDE_COMMAND`.
- nika never runs `kill-pane` or kills a process. Stop = `Escape`. End = `C-u`, `/exit`, `Enter`.
- Mode switch: idle only, ≤ 6 `BTab` presses, footer re-read after each, one switch in flight per pane; presses count
  toward the 20 requests/s key limit.
- Manual is reported only on a positive footer marker. No recognized phrase = `unknown`. An unrecognized footer that
  contains "bypass" = `bypassPermissions`.
- Agent-writable files are read through `src/fsafe.js` (O_NOFOLLOW, regular, user-owned, bounded); display text
  goes through `clean()` (`src/text.js`); the page renders with `textContent` only. No HTML sinks, no inline script
  or style. No `color-mix()` and no `:has()` in CSS (WebKitGTK).
- Mode styling: every mode has its own color token, icon and label; text ≥ 4.5:1, frame ≥ 3:1, light and dark;
  never color alone; mode changes announced through `aria-live="polite"`.
- `MODEL_ID` = `^(?:claude-[a-z0-9-]{3,60}|opus|sonnet|haiku|fable|best|opusplan)(?:\[1m\])?$`.
- Every route, collector, store function and write path has a `(+)` and a `(−)` test. `test/hygiene.test.js` stays
  green. Fixtures are synthetic: footer phrases and prompt layouts are typed by hand from `docs/contracts/claude-tui.md`.
- Branch `feat/0.3-session-control` cut from `master`. Commits use the repo's style (one imperative sentence, no
  prefix, no AI attribution). Subagents never commit: the orchestrator commits under the standing approval recorded in
  Task 0.

## Review Focus

1. A TUI overlay (slash-command menu, long multi-line input, a dialog) hides the footer. Expected: mode reads
   `unknown` and the switcher disables; never stale, never Manual. Test pinned in Task 4.
2. A narrow pane truncates the footer phrase. Expected: match on the shortest distinctive token from
   `claude-tui.md`; otherwise `unknown`. Test pinned in Task 4.
3. Claude turns busy between the click and a `BTab` press. Expected: idle is re-checked (registry state and no prompt)
   before every press; the switch stops with 409 `not-idle`. Test pinned in Task 6.
4. Composer text that starts with `/` but is not a command (a path such as `/usr/bin/env`). Expected: the palette shows
   no match and Enter sends the text unchanged. Test pinned in Task 11.
5. End session when a custom command starting with `exit` exists, or Claude does not quit. Expected: nika reports
   `{ended: false}` with the "Claude didn't exit" message, never a false success. Test pinned in Task 6. V15 checks
   the slash menu.

### Task 6: Session controller (Sonnet; after Task 4)

**Files:**
- Create: `src/session-control.js`
- Test: `test/session-control.test.js`

**Interfaces:**
- Consumes: `modeFromRows`, `promptFromRows`, `MODE_TARGETS` (Task 4); `mirror.capture(pane)` → `{ status, body: { rows } }`; `keys.send(pane, { text?, keys? })` → `{ status, body }`.
- Produces: `createSessionControl({ mirror, keys, paneCommand, now = Date.now, sleep, pollMs = 300, settleMs = 1800, maxPresses = 6, escWaitMs = 1000, exitWaitMs = 3000 })` where `paneCommand(pane) → Promise<string|null>` (null = pane gone), returning:
  - `switchMode(pane, target, { state, startMode }) → Promise<{ status, body }>`: 200 `{ mode, presses }`; 400 `invalid` (target not in `MODE_TARGETS`); 409 `{ error: 'not-idle' | 'mode-unknown' | 'not-in-cycle' | 'busy-switching' }`.
  - `endSession(pane, { state }) → Promise<{ status: 200, body: { ended: boolean } }>`.
- Rules: idle = `state === 'idle'` and `promptFromRows(rows) === null`, checked before every press. The current mode is `modeFromRows(rows)`, or `startMode` when that is `unknown` and `startMode` is given (for the first read only). `not-in-cycle` when the mode returns to the start mode without hitting the target. Each press = `keys.send(pane, { keys: ['BTab'] })`, then poll `mirror.capture` every `pollMs` until the mode changes or `settleMs` passes (then `mode-unknown`). End: if `state === 'busy'`, send `Escape` and `sleep(escWaitMs)`; then `keys: ['C-u']`, `text: '/exit'`, `keys: ['Enter']`; then poll `paneCommand` every 500 ms until it is null or fails `CLAUDE_COMMAND`, up to `exitWaitMs`.

  - `(+) already in target → 200 presses 0, no keys sent`
  - `(+) manual → plan presses BTab twice (manual → acceptEdits → plan)`
  - `(+) startMode is used when the first read is unknown`
  - `(−) target dontAsk → 400 invalid`
  - `(−) state busy → 409 not-idle, no keys sent`
  - `(−) prompt open → 409 not-idle`
  - `(−) becomes busy after the first press → 409 not-idle, one press sent` (Review Focus 3)
  - `(−) returns to the start mode without the target → 409 not-in-cycle`
  - `(−) footer unknown mid-cycle → 409 mode-unknown`
  - `(−) 6-press cap → 409 not-in-cycle after 6 presses`
  - `(−) second switch on the same pane while one runs → 409 busy-switching`
  - `(+) endSession idle: keys C-u, text /exit, keys Enter in that order; paneCommand → zsh → ended true`
  - `(+) endSession busy: Escape first, then the same sequence`
  - `(+) endSession: pane gone → ended true`
  - `(−) endSession: claude still running after exitWaitMs → ended false` (Review Focus 5)
  - `(−) endSession: keys.send returns 429 → ended false, sequence stopped`
