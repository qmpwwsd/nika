# nika project rules

Scope: binding for every session and agent working in this repository. They extend `~/.claude/ORCHESTRATION.md`; on a conflict this file wins.

## What nika is

A local dashboard and control panel for the Claude Code agents on this machine, grouped by git repository, in two tiers:

- **Browser tier (read-only)**: `nika serve` on `127.0.0.1:3335`, installed with Homebrew (`brew install qmpwwsd/tap/nika`) and run as a launchd/systemd service (`brew services start nika`). Lists agents; its only side effect is tmux focus. Unchanged from 0.1.
- **App tier (privileged)**: the desktop app (Tauri v2, macOS and Linux, tray icon) runs its own private server `nika serve --app` on `127.0.0.1:<random port>`, child of the app, secret handed over stdin. Only this tier has history, pane mirror and input, spawn, start orchestrator, add project, settings and apply rules (`/api/app/*`). These routes are never mounted on :3335.

Contracts: `docs/contracts/api-app.md`. Decisions: `docs/adr/`.

## Stack and commands

- Node >= 22, ES modules, **zero npm runtime and dev dependencies** (stdlib only). A new npm dependency needs the owner's approval.
- Rust (Tauri v2) for the desktop shell only, under `app/src-tauri`. Approved by the owner on 2026-11-08: `tauri` (tray-icon, image-png), `tauri-build`, `tauri-plugin-single-instance`, `tauri-plugin-dialog`, `tauri-plugin-autostart`, `serde`, `serde_json`. Versions pinned, `Cargo.lock` committed, `cargo audit` in CI. Any other crate is a new approval. Build tools approved by the owner on 2026-11-08, installed with `cargo install --locked` at pinned versions, never compiled into the app: `tauri-cli` (bundles) and `cargo-audit` (CI). Bundle id `io.github.qmpwwsd.nika`, display name `nika`.
- Tests: `node --test "test/*.test.js"` (`npm test`); `cargo test` under `app/src-tauri`. Every collector, route, store function and write path has a `(+)` case and a `(−)` case. `test/hygiene.test.js` must stay green: no home paths, scratchpad paths, emails, real-looking session ids or UUIDs, API keys or `.local` hosts anywhere in the repo.
- Run locally: `node bin/nika serve`, `node bin/nika status`; app tier: `node bin/nika serve --app` with a piped stdin (`hello` line), or `nika app`.
- Formula lives in the separate repo `qmpwwsd/homebrew-tap` (`Formula/nika.rb`).

## Security constraints (never relax)

1. The server binds `127.0.0.1` only and rejects any `Host` header other than `127.0.0.1:<port>` or `localhost:<port>`.
2. State-changing routes (`POST /api/focus`) require `Content-Type: application/json`, the per-process `X-Nika-Token`, and a matching `Origin` when present. No CORS headers.
3. Subprocesses run with `execFile` and fixed argument arrays, never through a shell. A tmux pane id must match `^%\d+$` and exist in the current `list-panes` output. tmux shell-commands are passed as multiple arguments (no `sh -c`); session names match `^[A-Za-z0-9_][A-Za-z0-9_-]{0,47}$` and targets are exact (`=<name>`, `%n`); `send-keys` text always follows `-l --`. tmux format-expands `-c` (a start directory is passed through `tmuxLiteral`, every `#` doubled) and also `new-session -s`, `new-window -n` and `select-pane -T`: those three are safe only because `TMUX_SESSION`, `AGENT_NAME` and nika's constant window names and titles contain no `#`, and a test asserts it.
4. nika never reads `*.key` files, `daemon/control.key`, `.env*`, `cc-socks`, the `hooks`, `permissions`, `env`, `apiKeyHelper`, `mcpServers` or `model` keys of any Claude settings file, or any credential path. The one exception is a project's `.claude/settings.local.json` at rules-apply time: nika parses the file as JSON to merge `enabledPlugins`, but never interprets, shows or sends any other key (they are copied verbatim, and the apply keeps a byte-for-byte backup of the file in nika's state dir). The browser tier reads only: `sessions/<pid>.json`, `projects/**/<uuid>.jsonl` (head and tail chunks), `subagents/*.meta.json`, spawn report files (`<name>.session|.md|.rc`, in the scratchpad and in nika's own `reports/` dirs), nika's own `config.json` (project list only) and `.git` / `commondir` files. The app tier additionally reads: full transcripts, paginated with bounded windows; `tmux capture-pane` of live Claude panes and nika-started panes only, and only while the pane's current command looks like claude (`CLAUDE_COMMAND`; a stale or reused pane id never qualifies); the installed plugin names; a project's `rules/orchestration.md`, `CLAUDE.md`, `.claude/settings.local.json` and `.gitignore` for preview.
5. A file path never comes from a request. Report files are looked up by session id in the index nika built itself. Projects enter only through the native folder picker or `nika projects add <dir>` on the CLI, are stored as realpath and referenced by key (`^[a-z0-9]{16}$`, sha256 of the realpath) everywhere else.
6. Every transcript-, pane- or report-derived string is rendered with `textContent`; the page ships a strict CSP (no inline script or style). The pane mirror keeps only whitelisted SGR codes server-side; OSC, DCS, other CSI and C0/C1 never reach the page.
7. Test fixtures are synthetic. Never copy a real transcript, session file, account id, prompt, rules file or path into the repository. Rule templates under `templates/` are written from scratch, never copied from a private project or `~/.claude`.
8. No hardcoded user paths: use `os.homedir()`, `CLAUDE_CONFIG_DIR`, `process.getuid()`, `XDG_*` via `src/paths.js`.
9. Every file under `~/.claude`, a scratchpad, a project or nika's own dirs is agent-writable: read it through `src/fsafe.js` (O_NOFOLLOW, O_NONBLOCK, regular file owned by the user, bounded size), validate ids at the boundary (`src/ids.js`), and pass display text through `clean()` / `cleanBlock()` (`src/text.js`).
10. Single-user machine assumption: any local process can read the browser tier. The README says so; do not add data to :3335 that would make this worse (no secrets, no full transcripts). The app tier is reachable only with the per-launch secret: random port, 256-bit secret over stdin, `X-Nika-App` timing-safe, `Origin` / `Sec-Fetch-Site` checked, JSON for writes, `no-store`. The secret never touches argv, env, disk, logs or HTML markup.
11. **Writes.** nika writes only through `src/fwrite.js` (real user-owned dirs, targets absent or regular single-link user-owned files, O_EXCL temp file + fsync + rename, 0600/0700 for nika's own files; an existing in-project file keeps its mode minus group/other write, a new `settings.local.json` is 0600 and other new in-project files 0644; an in-project folder may be group-writable only on Linux when its group is the user's primary group, never world-writable). Its own files live in `${NIKA_CONFIG_DIR || XDG_CONFIG_HOME || ~/.config}/nika` and `${XDG_STATE_HOME || ~/.local/state}/nika`. Into a project it writes exactly `rules/orchestration.md`, `CLAUDE.md` (one `@rules/orchestration.md` line), `.claude/settings.local.json` (only `enabledPlugins`; all other keys copied verbatim and deep-equal asserted) and, opt-in, one `.gitignore` line; always after a diff preview, explicit confirmation and a hash check, with a byte-for-byte backup in nika's state dir, never inside the repo (the last 10 backup folders per project are kept; after a successful apply the older ones are removed, and only entries named like a stamp nika wrote that are real directories owned by you; a symlink, a file or any other name is never followed or deleted). After each in-project rename the directory chain is re-checked and the target must resolve inside the project root, else the file is unlinked and the write refused with `ESYMLINK` (`verifyInside`; a swap in the remaining window needs write access to the project folder, `docs/security.md` T8). nika never runs `git add`, `commit` or `push`. `config.json` is validated on load; garbage falls back to defaults with a warning.
12. **Agent control.** `bypassPermissions` is refused at the store, API and spawn layers. Spawned agents get `--disallowedTools` for `Bash(nika:*)`, `Bash(tmux:*)`, `Bash(claude:*)`, `Bash(git add:*)`, `Bash(git commit:*)`, `Bash(git push:*)` and a deny list for `.env*` and `*.key`. **These lists are advisory, not a security boundary.** Claude Code matches permission rules against the literal command text, so `/opt/homebrew/bin/tmux …`, `sh -c 'tmux …'`, `git -C . commit` or a script written with Write and run with Bash all pass, and Read/Edit denies do not cover subprocesses. The lists stop the common invocation and honest mistakes; the boundary is the single-user trust model (constraint 10) plus the app secret. There is no Claude Code sandbox in 0.2; it is planned as an optional Settings switch (owner decision 2026-11-08). The guard prompt wording stays as is. Keystrokes go only to live Claude panes or nika-started panes, and only while the pane's current command looks like claude; text ≤ 1024 chars without controls, multi-line paste ≤ 16 KB only through tmux bracketed paste (`load-buffer -` + `paste-buffer -p -d`; only `\n` `\t` kept, ESC and every other control stripped), named keys from the allow-list in `src/ids.js`, ≤ 8 per request, 20 requests/s per pane. A brief never passes through tmux argv (`_run-agent` reads it from a 0600 file); it is claude's own argv, which any local process can read with `ps` (constraint 10). A brief must be more than one word (a lone word such as `update` could be read by claude as a subcommand), checked in the API, the CLI, the spawn sheet and `_run-agent`. `limits.maxAgents` bounds live spawned agents, and the duplicate-name check uses the same list: both count the panes, in any tmux session, that tmux reports with `@nika-role` `agent` and an `@nika-agent` tag `<project key>/<name>` for this project (set by nika when it creates the pane; the tag is parsed strictly, key must match `PROJECT_KEY` and name `AGENT_NAME`, anything else is ignored and never trusted; the name check compares the exact `<key>/<name>`), plus panes this process started. `<name>.pane` files are agent-writable and display only: they never count. nika never kills or owns agent processes.
13. **Desktop shell.** The webview navigates only to its own origin; `https://claude.ai/code/session_<id>` opens in the system browser via fixed argv (`open` / `xdg-open`); everything else is blocked and `window.open` is denied. No Tauri capability is granted to the server origin (no `window.__TAURI__`). The shell talks to the server only through the stdio JSON-lines protocol (`docs/contracts/api-app.md` §5). The child runs with an env built from scratch (`env_clear`): `PATH`, `HOME`, `NIKA_APP=1` and, when set, `CLAUDE_CONFIG_DIR`, `NIKA_CONFIG_DIR`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `TMUX_TMPDIR`, `LANG`, `LC_ALL`, `LC_CTYPE`; nothing else is inherited, and `NIKA_NODE` only picks the node binary (it is not passed on). No telemetry: the only outbound connection nika ever makes is the claude.ai link the user clicks (asserted by `test/hygiene.test.js`).

## Git

- Default branch `master` (never `main`), the only long-lived branch. Each change happens on a short-lived branch cut from `master` (`feat/…`, `fix/…`, `docs/…`, `release/X.Y.Z`) and reaches `master` only through a reviewed PR with all CI checks green, as a merge commit; merged branches are deleted (a PR page can restore one). Commits only with the owner's explicit approval per commit (ORCHESTRATION §19). No AI attribution lines.
- Before each commit: `npm test` green (incl. hygiene) and `git diff master...HEAD` reviewed for paths, emails and ids.
- Publishing (repo creation, push, tags, releases, tap updates, CI workflow dispatch) needs the owner's approval for that specific action.
- Standing approvals (ORCHESTRATION §19) are recorded here with their date and branch, and end when that branch is merged. Ended: `fix/0.2.0-release` and `feat/release-drafts` (both granted and merged 2026-11-08).
- Releases (owner decision 2026-11-08): pushing a tag `vX.Y.Z` makes `release-linux.yml` build the Linux packages and create a draft release; it never publishes. Pushing the tag, publishing the draft and updating the tap each need the owner's approval. Procedure: `docs/packaging.md`, Release procedure.
