# nika project rules

Scope: binding for every session and agent working in this repository. They extend `~/.claude/ORCHESTRATION.md`; on a conflict this file wins.

## What nika is

A local dashboard and control panel for the Claude Code agents on this machine, grouped by git repository, in two tiers:

- **Browser tier (read-only)**: `nika serve` on `127.0.0.1:3335`, installed with Homebrew (`brew install qmpwwsd/tap/nika`) and run as a launchd/systemd service (`brew services start nika`). Lists agents; its only side effect is tmux focus. Unchanged from 0.1.
- **App tier (privileged)**: the desktop app (Tauri v2, macOS and Linux, tray icon) runs its own private server `nika serve --app` on `127.0.0.1:<random port>`, child of the app, secret handed over stdin. Only this tier has history, pane mirror and input, session control (mode, End, commands, models), spawn, start orchestrator, add project, settings and apply rules (`/api/app/*`). These routes are never mounted on :3335.

Contracts: `docs/contracts/api-app.md`. Decisions: `docs/adr/`.

## Stack and commands

- Node >= 22, ES modules, **zero npm runtime and dev dependencies** (stdlib only). A new npm dependency needs the owner's approval.
- Rust (Tauri v2) for the desktop shell only, under `app/src-tauri`. Approved by the owner on 2026-11-08: `tauri` (tray-icon, image-png), `tauri-build`, `tauri-plugin-single-instance`, `tauri-plugin-dialog`, `tauri-plugin-autostart`, `serde`, `serde_json`; on 2026-11-13: `objc2-foundation` (macOS only, to register nika's own press-and-hold default in memory). Versions pinned, `Cargo.lock` committed, `cargo audit` in CI. Any other crate is a new approval. Build tools approved by the owner on 2026-11-08, installed with `cargo install --locked` at pinned versions, never compiled into the app: `tauri-cli` (bundles) and `cargo-audit` (CI). Bundle id `io.github.qmpwwsd.nika`, display name `nika`.
- Tests: `node --test "test/*.test.js"` (`npm test`); `cargo test` under `app/src-tauri`. Every collector, route, store function and write path has a `(+)` case and a `(−)` case. `test/hygiene.test.js` must stay green: no home paths, scratchpad paths, emails, real-looking session ids or UUIDs, API keys or `.local` hosts anywhere in the repo.
- Run locally: `node bin/nika serve`, `node bin/nika status`; app tier: `node bin/nika serve --app` with a piped stdin (`hello` line), or `nika app`.
- Formula lives in the separate repo `qmpwwsd/homebrew-tap` (`Formula/nika.rb`).

## Security constraints (never relax)

1. The server binds `127.0.0.1` only and rejects any `Host` header other than `127.0.0.1:<port>` or `localhost:<port>`.
2. State-changing routes (`POST /api/focus`) require `Content-Type: application/json`, the per-process `X-Nika-Token`, and a matching `Origin` when present. No CORS headers.
3. Subprocesses run with `execFile` and fixed argument arrays, never through a shell. A tmux pane id must match `^%\d+$` and exist in the current `list-panes` output, or be the id tmux itself returned from `-P -F` a moment ago (`tagPane`, `earlyExit`); it is matched against `PANE_ID` either way. tmux shell-commands are passed as multiple arguments (no `sh -c`); session names match `^[A-Za-z0-9_][A-Za-z0-9_-]{0,47}$` and targets are exact (`=<name>`, `%n`); `send-keys` text always follows `-l --`. tmux format-expands `-c` (a start directory is passed through `tmuxLiteral`, every `#` doubled) and also `new-session -s`, `new-window -n` and `select-pane -T`: those three are safe only because `TMUX_SESSION`, `AGENT_NAME` and nika's constant window names and titles contain no `#`, and a test asserts it. tmux `new-session -e` and `new-window -e` (0.4, ADR 0014) take a literal value (no format expansion; spike S2), and nika passes only the two auto-compact names, each with a value `compactLaunch` made of digits and at most one dot. `new-session -e` is session-scoped, so right after it nika runs `set-environment -t =<session> -u <NAME>` for each of the two names (fixed argv, exact target, best effort); `new-window -e` is pane-only. `new-session -e` needs tmux 3.2. Pane tags are set with `set-option -p` and fixed argv arrays (their values are not format-expanded, and none contains `#`): `@nika-role` is `orchestrator`, `sub-orchestrator` or `agent`, `@nika-agent` is `<project key>/<AGENT_NAME>` built from validated parts (an orchestrator's is `<project key>/orchestrator`, set when nika starts, resumes or adopts it), and (0.4, ADR 0013) `@nika-depth` is a constant `1`, `2` or `3` that nika computes from the parent's role and `@nika-parent` is a pane id (`^%\d+$`) taken from tmux's own listing, never request data, argv, env or a file. (0.5, W9) `@nika-kind` is set only on an agent pane (never on an orchestrator or a sub-orchestrator), with the last `set-option -p` call of the spawn, and is one of seven constant words, `coder`, `reviewer`, `tester`, `designer`, `scout`, `writer` or `agent`: the spawn's `kind` (checked against `KINDS` in `src/ids.js` by the API, the CLI, `spawnAgent` and again by `tagPane`, so no other text from a request reaches tmux) or, without one, the word nika derives at spawn from the spawn's own model and the project's effective role models (`builder` → coder, `reasoner` → designer, `scout` → scout; no single match → agent). **Fit (0.5, ADR 0017).** To make the mirrored pane fill the session window the app tier runs, for one eligible pane `%P` and its window `@W` only: `resize-pane -Z -t %P`, `resize-window -t @W -x <C> -y <R>`, `set-option -w -t @W @nika-fit <nonce>` and `set-option -wu -t @W @nika-fit`, `set-option -w -t @W window-size <latest|largest|smallest|manual>` and `set-option -wu -t @W window-size`, `select-layout -t @W -- <layout>` and `select-pane -t <pane>`; it reads with `list-panes -a -F <constant>`, `display-message -p -t @W -F '#{window_layout}'` and `show-options -w -t @W window-size`; and `spawn` reads `display-message -p -t <=session:|%n> -F '#{window_id}'` before a split into a session that already exists, only while the fit holds a window. `@W` matches `^@\d{1,6}$` and `%P` and `<pane>` match `^%\d+$`, all taken from tmux's own output in the same call, never from a request, argv or env; a file gives them only at the next start (nika's own 0600 lease file), and only while tmux's listing in the same call shows the window's `@nika-fit` tag equal to the file's nonce. `<C>` and `<R>` are integers: the route checks 40–400 and 10–200, `src/fit.js` checks them again, and a window's saved size is 1–10000. The nonce is 16 hex from nika's CSPRNG. The layout is tmux's own `#{window_layout}` output (printable ASCII, 1–8192 characters, no `#`, the 3.8 `"a"` and `"l"` markers removed), kept only in nika's 0600 lease file and applied only while `@nika-fit` still equals that nonce. `set-option` values are literal (not format-expanded), `-x` and `-y` are digits and every `-F` string is a constant, so no `#` reaches a format-expanded argument. nika never toggles a zoom it did not make (it reads `#{window_zoomed_flag}` and the active pane first), never resizes a window with several panes below its original size, never applies a saved layout when the layout, the pane count or a zoom changed, and never retries a restore in a loop. Every fit call is built by one table of validating builders (`ARGV` in `src/fit.js`); no other fit tmux call can be built, and `test/fit.test.js` fails on any argv outside it.
4. nika never reads `*.key` files, `daemon/control.key`, `.env*`, `cc-socks`, the `hooks`, `permissions`, `env`, `apiKeyHelper`, `mcpServers` or `model` keys of any Claude settings file, or any credential path. The one exception is a project's `.claude/settings.local.json` at rules-apply time: nika parses the file as JSON to merge `enabledPlugins`, but never interprets, shows or sends any other key (they are copied verbatim, and the apply keeps a byte-for-byte backup of the file in nika's state dir). The browser tier reads only: `sessions/<pid>.json`, `projects/**/<uuid>.jsonl` (head and tail chunks; from the tail, also the `usage` numbers and the model id of the last assistant entry, nothing else of it: the context size, 0.4), `subagents/*.meta.json`, spawn report files (`<name>.session|.md|.rc`, in the scratchpad and in nika's own `reports/` dirs), nika's own `config.json` (project list, per-project config and the compaction setting), the pane tags nika sets itself (`@nika-role`, `@nika-agent`, `@nika-depth`, `@nika-parent` and (0.5, W9) `@nika-kind`, the last only beside `@nika-role agent` and only as one of the seven words, from `tmux list-panes`, each parsed strictly and dropped when it does not parse; 0.4), `.git` / `commondir` files and, on Linux, `/proc/<pid>/stat` of the registry pids whose `procStart` is digits (the `starttime` field only, ≤ 4 KB). The app tier additionally reads: full transcripts, paginated with bounded windows: a session's own and (0.5, W8) its subagents' `subagents/agent-<id>.jsonl`, found in nika's own listing of that session's `subagents/` folder (real directories only), and from `subagents/*.meta.json` also `toolUseId` (parsed by the shared collector in both tiers, used only by the app tier and only for an equality check, never shown or sent); `tmux capture-pane` of live Claude panes and nika-started panes only, and only while the pane's current command looks like claude (`CLAUDE_COMMAND`; a stale or reused pane id never qualifies); the installed plugin names and their `installPath` values in `installed_plugins.json` (a path is used only when its realpath is inside `<claude dir>/plugins/cache`; `<claude dir>` is the Claude config dir, `CLAUDE_CONFIG_DIR`, default `~/.claude`); the YAML frontmatter (first 4 KB; keys `name`, `description`, `argument-hint`, `user-invocable`; never the body) of top-level command and skill files in `<claude dir>/{commands,skills}`, `<project>/.claude/{commands,skills}` and installed plugins' `commands/` and `skills/` (0.3); a project's `rules/orchestration.md`, `CLAUDE.md`, `.claude/settings.local.json` and `.gitignore` for preview and apply, and a project's `AGENTS.md` (G7, 2026-11-14): its type first with `lstat` without following (absent, regular file, symlink or other), and its content only when it is a regular file, read through `src/fsafe.js` like `CLAUDE.md` (no follow, user-owned, single link, bounded, UTF-8; a buffer sized by the file) for the preview and the apply. The rules state (the project list's badge on every poll, and `nika projects list`) reads `rules/orchestration.md`, `CLAUDE.md`, `AGENTS.md` (same rules) and `.gitignore` the same way, and never opens a symlink, folder or FIFO. The app tier also reads the files the user picks in the attach chooser (0.5, W2-T6): the shell's native dialog returns absolute paths and the server opens each one through `src/fsafe.js` `openRegular` (O_NOFOLLOW, a regular file owned by the user, one link), refuses a size above 8 MiB from the fstat before it reads a byte, reads the file once into memory and hands the bytes to the attachment store; a name on the secret-name list (`docs/security.md` T55) is refused before the file is opened, and the upload refuses the same names. At most 6 files are read per pick, nothing about a path or a name is logged, and the path is dropped after the read. On macOS the CLI and the app tier also read `Contents/Info.plist` (≤ 64 KB, bundle id and version only) of nika's own app bundles: the source and `~/Applications/nika.app` (ADR 0011). **Fit (0.5):** for the mirrored pane's window the app tier also reads, from tmux and in the same call, `#{window_id}`, `#{window_panes}`, `#{window_zoomed_flag}`, `#{pane_active}`, `#{window_width}` / `#{window_height}`, `#{pane_width}` / `#{pane_height}`, `#{window_layout}` and the window-level `window-size` option; (F2) each pane's `#{@nika-role}`, compared only with `agent` and `sub-orchestrator`; (F4) each window's `#{window_active_clients}`, read as digits and compared only with 0 (every kind of client counts: control mode, `ignore-size` and read-only included); the window tag `@nika-fit` that nika sets itself (read strictly as 16 hex, anything else counts as foreign and is never trusted); and nika's own lease files `<state>/fit/fit-<16 hex>.json` (at most 20, each ≤ 16 KB, through `src/fsafe.js`, every field shape-checked). The browser tier reads none of this. The app tier opens its own attachment files under `<state>/attachments/` through `fsafe` (O_NOFOLLOW, regular, owned by the user, one link) only to check them before a send, and never reads their content back; it reads `attachments.keepDays` from its own `config.json`. **Scroll (0.5, W3):** with each capture the app tier also reads the pane's `#{alternate_on}` (in the same `display-message` as the size and cursor). nika reads no tmux scrollback of a pane (`capture-pane -S`).
5. A file path never comes from a request. Report files are looked up by session id in the index nika built itself. A subagent transcript is looked up by session id in nika's transcript index and by subagent id in nika's own listing of that session's `subagents/` folder (0.5, W8). Projects enter only through the native folder picker or `nika projects add <dir>` on the CLI, are stored as realpath and referenced by key (`^[a-z0-9]{16}$`, sha256 of the realpath) everywhere else. An attachment enters as bytes, either in a JSON upload from the session window (paste or drop) or read by the server itself from a file the user picked in the attach chooser (0.5, W2): the user's file name never reaches the disk (only an extension from a fixed list), the stored name is a random id nika made, and a send names attachments by those ids, never by a path. The one other path the server ever reads comes from the attach chooser: a picked path travels only from the shell to the server over stdio (`files`, `docs/contracts/api-app.md` §5), is opened once and dropped, and never goes to the page, an answer, a log or a request (the route that starts the chooser takes `{ room }` and nothing else, and no answer holds a path).
6. Every transcript-, pane- or report-derived string is rendered with `textContent`; the page ships a strict CSP (no inline script or style). The pane mirror keeps only whitelisted SGR codes server-side; OSC, DCS, other CSI and C0/C1 never reach the page.
7. Test fixtures are synthetic. Never copy a real transcript, session file, account id, prompt, rules file or path into the repository. Rule templates under `templates/` are written from scratch, never copied from a private project or `~/.claude`.
8. No hardcoded user paths: use `os.homedir()`, `CLAUDE_CONFIG_DIR`, `process.getuid()`, `XDG_*` via `src/paths.js`.
9. Every file under `~/.claude`, a scratchpad, a project or nika's own dirs is agent-writable: read it through `src/fsafe.js` (O_NOFOLLOW, O_NONBLOCK, regular file owned by the user, bounded size), validate ids at the boundary (`src/ids.js`), and pass display text through `clean()` / `cleanBlock()` (`src/text.js`).
10. Single-user machine assumption: any local process can read the browser tier. The README says so; do not add data to :3335 that would make this worse (no secrets, no full transcripts). The app tier is reachable only with the per-launch secret: random port, 256-bit secret over stdin, `X-Nika-App` timing-safe, `Origin` / `Sec-Fetch-Site` checked, JSON for writes, `no-store`. The secret never touches argv, env, disk, logs or HTML markup. Attachments (0.5) are app tier only: the upload is JSON with base64, at most 12 MiB, one at a time, at most 30 a minute; no route serves an attachment back.
11. **Writes.** nika writes only through `src/fwrite.js` (real user-owned dirs, targets absent or regular single-link user-owned files, O_EXCL temp file + fsync + rename, 0600/0700 for nika's own files; an existing in-project file keeps its mode minus group/other write, a new `settings.local.json` is 0600 and other new in-project files 0644; an in-project folder may be group-writable only on Linux when its group is the user's primary group, never world-writable). Its own files live in `${NIKA_CONFIG_DIR || XDG_CONFIG_HOME || ~/.config}/nika` and `${XDG_STATE_HOME || ~/.local/state}/nika`. Attachments (0.5, W2, ADR 0016): `<state>/attachments/<key>/<id>.<ext>` (0700 folders, 0600 files, `<key>` the pane's repository key from nika's own snapshot, `<id>` 16 random hex, the type from the bytes: png, jpeg, gif, webp, pdf or UTF-8 text); they are removed when the user removes them before sending, when the session window closes with them unsent, after `attachments.keepDays` (1–30, default 7; checked after start, every 24 h and before each save), and oldest first beyond 256 MiB or 500 files (never one younger than 1 h); only names nika writes that are regular single-link files of the user are removed, and nothing is followed. Into a project it writes exactly `rules/orchestration.md`, `CLAUDE.md` (one `@rules/orchestration.md` line), `AGENTS.md` when it is a regular file (the same one line), `.claude/settings.local.json` (only `enabledPlugins`; all other keys copied verbatim and deep-equal asserted) and, opt-in, one `.gitignore` line; always after a diff preview, explicit confirmation and a hash check, with a byte-for-byte backup in nika's state dir, never inside the repo (the last 10 backup folders per project are kept; after a successful apply the older ones are removed, and only entries named like a stamp nika wrote that are real directories owned by you; a symlink, a file or any other name is never followed or deleted). After each in-project rename the directory chain is re-checked and the target must resolve inside the project root, else the file is unlinked and the write refused with `ESYMLINK` (`verifyInside`; a swap in the remaining window needs write access to the project folder, `docs/security.md` T8). nika never runs `git add`, `commit` or `push`. **`AGENTS.md` and `CLAUDE.md` (G7, owner decision 2026-11-14):** other coding tools read `AGENTS.md`, Claude reads `CLAUDE.md`, so both carry the line, and Claude must load the rules once. `AGENTS.md` is written before `CLAUDE.md`, with the same backup, hash check, `verifyInside` and mode rules; a `CLAUDE.md` with an `@AGENTS.md` (or `@./AGENTS.md`) import line outside a code fence, beside a regular `AGENTS.md`, gets the rules through it and is left as it is (nika never adds the line there and never removes one; if it has its own line from an earlier apply, the preview says Claude may read the rules twice); a project with only a regular `AGENTS.md` gets a new `CLAUDE.md` whose whole content is `@AGENTS.md`. A symlinked, folder, FIFO or other non-regular `AGENTS.md` is never followed or opened: beside a `CLAUDE.md` it is shown as `skipped` with a note and `CLAUDE.md` gets the line itself; alone it refuses the apply (`ESYMLINK` for a symlink, `ENOTREG` otherwise). **App copy (owner decision 2026-11-09, ADR 0011):** on macOS nika also writes exactly `~/Applications/nika.app`, a `ditto` copy of the nika.app that came with this install, only on `nika app install`, the app's Add/Update button, or a launch command refreshing a copy nika made before (state marker) after an upgrade. The source is derived from the install, never from a request or a file; the target is replaced only when it is a real folder you own whose Info.plist names nika's bundle id; the copy is built in a temp sibling and swapped in with rename. Never `/Applications`, never sudo. `config.json` is validated on load; garbage falls back to defaults with a warning. **Fit lease files (0.5, ADR 0017):** nika also writes `<state>/fit/fit-<nonce>.json` (0600 in a 0700 folder, by `writeAtomic`; before the first tmux change of a fit and again after each resize) and removes it with `removeOwnFile(dir, name)` in `src/fwrite.js`: the folder must be a real user-owned one, the file is looked at with `lstat` and never followed, and it is removed only when it is a regular, single-link, user-owned file (a symlink, a folder, a FIFO, a second link or a foreign owner is refused with `ESYMLINK`, `ENOTREG`, `ENLINK` or `EOWNER`). At the app tier's start at most 20 files are read back; a file that does not parse is removed, never used.
12. **Agent control.** `bypassPermissions` is refused at the store, API and spawn layers, for the Settings default and for each project's own `perProject.<key>.permissionMode` (0.4.0), and the mode switch never targets it (0.3; it may pass through it on the way to another mode when Claude's cycle holds it). Spawned agents get `--disallowedTools` for `Bash(nika:*)`, `Bash(tmux:*)`, `Bash(claude:*)`, `Bash(git add:*)`, `Bash(git commit:*)`, `Bash(git push:*)` and a deny list for `.env*` and `*.key`. **These lists are advisory, not a security boundary.** Claude Code matches permission rules against the literal command text, so `/opt/homebrew/bin/tmux …`, `sh -c 'tmux …'`, `git -C . commit` or a script written with Write and run with Bash all pass, and Read/Edit denies do not cover subprocesses. The lists stop the common invocation and honest mistakes; the boundary is the single-user trust model (constraint 10) plus the app secret. There is no Claude Code sandbox in 0.2; it is planned as an optional Settings switch (owner decision 2026-11-08). The guard prompt wording stays as is. Keystrokes go only to live Claude panes or nika-started panes, and only while the pane's current command looks like claude; text ≤ 1024 chars without controls, multi-line paste ≤ 16 KB only through tmux bracketed paste (`load-buffer -` + `paste-buffer -p -d`; only `\n` `\t` kept, ESC and every other control stripped), named keys from the allow-list in `src/ids.js`, ≤ 8 per request, 20 requests/s per pane. Session control (0.3, ADR 0010): Stop is its own route (`POST /api/app/pane/:id/stop`, outside the per-pane lock): only for a busy registry state with no prompt on screen it sends `Escape`, and when Claude's input is in vim insert mode (`-- INSERT --` shown) a second `Escape` only after the insert marker has gone and a state read that skips the registry cache still says busy; idle, no state or a prompt on screen send nothing (409). One interrupt runs per pane at a time, shared with End and kept apart from the lock (an overlapping Stop is 409 `stopping`, an overlapping End 409 `not-idle`, nothing sent). The keys route (the page's passthrough uses it too) refuses (409 `bypass-prompt`, nothing sent) a request with `Enter`, a digit in `text` or any `paste` while a permission prompt, or a dialog whose footer nika cannot read, with a window (the last 15 non-blank rows) that mentions bypass is on screen, after a fresh capture; only the terminal itself can answer such a prompt. Send's own typing (body `send: true`) also takes a fresh capture first and is refused (409, nothing sent) while a permission prompt, a dialog, Claude's feedback survey or an unknown footer with no input box is on screen; each chunk of a long text is checked again. End session takes a fresh capture; for a permission prompt on screen it sends `Escape` (the "No" path) and for a busy registry state it interrupts as Stop does, but with no registry state and no prompt it sends no key; it then waits 1 s and captures again; Claude still busy, a prompt still on screen, an unrecognized footer (a dialog may be open) or a non-empty input box refuses with 409 and types nothing; in vim normal mode it first types `i` and checks for `-- INSERT --`; it types `/exit` and presses `Enter` only when the input box then reads exactly `❯ /exit` with no ghost text after it (else it sends `C-u` to remove its own text and refuses), and reports `ended` only when the pane is gone or no longer runs claude within 3 s; nika never runs `kill-pane` and never signals a process. When nothing shows that vim is on, End and the quick-action commands type a command's first character `/` alone and read the screen (plain input: the rest follows; Claude's history search from vim normal mode: one `Escape`, then the `i` road; anything else, or a failed send of the rest: `/` removed, 409). A permission-prompt answer goes through a fresh capture and a signature check of the prompt rows (the page's `sig` must match), and only a digit among the shown options is typed; an option is never answered by nika when the prompt window, the option's label or its wrapped text mentions bypass. **Feedback survey (0.5, F14).** Claude's feedback survey (`How is Claude doing this session? (optional)` with the row `1: Bad  2: Fine  3: Good  0: Dismiss` right below it) is answered only through `POST /api/app/pane/:id/survey { n, sig }` (app tier only), under the per-pane lock, while no Stop or End interrupt runs or sent its `Escape` less than 40 ms ago: after one fresh capture that shows exactly those two rows once, above Claude's input box, with no permission prompt or dialog, the page's `sig` (16 hex of sha256 over the two rows and the rows just above them) matching, no mention of bypass in the last 15 non-blank rows, Claude's input box empty with the cursor in it, the input not in vim normal mode and the registry state idle (read fresh), nika types the one digit among the shown options (0 to 3) as literal text, never `Enter` or any other key, and reads the screen back for at most 1 s. For 4 s after a rating of 1 to 3, while Claude offers `Esc to undo`, nika sends no Escape of its own: Stop, End, the commands, Send and the dialog form's Decline answer 409 `survey-undo` and send nothing; keys the user types through the keys route still pass. The follow-up question whether Anthropic may look at the session transcript is answered the same way and with the same checks, only in the exact layout recorded in `docs/contracts/claude-tui.md`, and the page says next to its buttons that a yes shares the session's transcript with Anthropic. The other survey questions and any layout nika does not know are never answered by nika; the page says to answer them in the terminal. **Dialogs (0.5, W1, ADR 0015).** Claude's question dialog (`AskUserQuestion`) and plan approval (`ExitPlanMode`) are read only from the pane's screen (constraint 4 already allows the capture) and answered only through `POST /api/app/pane/:id/dialog`, one step per request (the current question, the review's Submit, a plan choice, or Decline), under the per-pane lock. A step is answered only when the screen shows it in full: no row reaches the pane's last column unless the row below continues the same question or description, the question's rows all start with Claude's `│ ` bar, which nika leaves out, or none does, no label could be a wrapped one, no text ends in `…`, the strip has exactly one current tab, options are numbered 1 to 9 and a feedback survey is not on screen; anything else is `unreadable` and the page keeps its banner. It is answered only with the `sig` nika computed from a fresh capture (16 hex of sha256 over the parsed step). Before every key a fresh capture must show the same step in the state the previous key should have left, and nothing a person could have changed in the terminal (the focus, the boxes, the typed text, the INSERT marker) may differ from the screen the last key was proven on; else nothing more is sent (409, with the number of keys already pressed). nika sends: a digit 1 to 9 as literal text, only on a numbered option with the focus off the free-text row (a plan choice is a digit too); `Down`; `Right`, only from an option row; `Enter` only on the focused free-text row after it reads back exactly the typed text, on the multi-select question's button row after its Other text (the last tab only), or on the review's `1. Submit answers`; `Escape` only for the user's Decline (a second one, 40 ms later, only when a fresh read shows the first left vim insert mode); free text through `send-keys -l` (1 to 300 characters, no control, bidi, zero-width or other format character, no space at either end, not starting with 1 to 9), typed only in vim insert mode, on a pane known to be plain, or right after nika's own `Down` brought the focus onto the text row. ## Git

- Default branch `master` (never `main`), the only long-lived branch. Each change happens on a short-lived branch cut from `master` (`feat/…`, `fix/…`, `docs/…`, `release/X.Y.Z`) and reaches `master` only through a reviewed PR with all CI checks green, as a merge commit; merged branches are deleted (a PR page can restore one). Commits only with the owner's explicit approval per commit (ORCHESTRATION §19). No AI attribution lines.
- GitHub enforces this (owner decision 2026-11-09, repository rulesets): `master` takes changes only through a PR merged as a merge commit, with 1 approving review (a new push dismisses it; conversations resolved) and the six CI checks green from GitHub Actions (`node (macos-latest)`, `node (ubuntu-latest)`, `rust (macos-latest)`, `rust (ubuntu-22.04)`, `gui-smoke`, `linux-verify`) on a branch up to date with `master`; no deletion, no force push. Repository admins may bypass (the owner merges their own PRs with the bypass, since nobody can approve their own PR; GitHub logs each bypass), and a bypass is still a merge that needs the owner's approval. `v*` tags cannot be deleted or moved, with no bypass. Squash and rebase merges are off; head branches are deleted after a merge. A renamed CI job must be renamed in the ruleset in the same PR, or every PR stays blocked.
- Before each commit: `npm test` green (incl. hygiene) and `git diff master...HEAD` reviewed for paths, emails and ids.
- Publishing (repo creation, push, tags, releases, tap updates, CI workflow dispatch) needs the owner's approval for that specific action.
- Standing approvals (ORCHESTRATION §19) are recorded here with their date and branch, and end when that branch is merged. Active: `feat/0.4-fixes` (granted 2026-11-13) and the work branches of releases 0.5 and 0.6 (`feat/0.5-*`, `feat/0.6-*`, granted 2026-11-09); each ends when its branch is merged. Ended: `fix/0.2.0-release` and `feat/release-drafts` (both granted and merged 2026-11-08), `feat/0.3-session-control` (granted 2026-11-08, merged 2026-11-09), `fix/0.3.4-fixes` (merged 2026-11-09), `feat/0.4-orchestration` (merged 2026-11-13).
- Releases (owner decision 2026-11-08): pushing a tag `vX.Y.Z` makes `release-linux.yml` build the Linux packages and create a draft release; it never publishes. Pushing the tag, publishing the draft and updating the tap each need the owner's approval. Procedure: `docs/packaging.md`, Release procedure.
